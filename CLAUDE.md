# Projektregeln – Mängel-App Sportplatz

- Konzept und Entscheide: `KONZEPT.md`. Vor jeder Arbeit lesen.
- Eigenständiges Projekt ohne Bezug zum BaustellenPlaner. Keinen Code oder Daten von dort übernehmen.
- Sprache: Deutsch (Schweiz, kein ß), Anrede immer «du» – in der Oberfläche und in Antworten.
- Oberfläche einfach, übersichtlich, für die Bedienung auf dem Handy mit dem Daumen gemacht.
- Technik: plain HTML/CSS/JavaScript ohne Framework und ohne Build-Schritt. Externe Bibliotheken nur mit fester Version.
- Daten bleiben auf dem Gerät; keine Übertragung an fremde Server ausser Kartenkacheln von swisstopo.
- Git: `main` = stabil; Arbeit auf `feature/*` oder `fix/*`. Commit, Push und Merge jeweils nur nach Freigabe durch Danick.
- git liegt nicht im PATH: `C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\TeamFoundation\Team Explorer\Git\cmd\git.exe`
- Ablauf je Etappe: Stand prüfen → Vorschlag zeigen → erst nach Freigabe umsetzen → testen (nicht Geprüftes kennzeichnen) → kurz berichten, was Danick auf dem Handy testen soll.
- Antworten kurz, Änderungen als Liste, immer sagen, was Danick jetzt tun soll.
